QUESTION 1: WHAT IS A MISSING VALUE?
═════════════════════════════════════════════════════════════════════════════════

DEFINITION:
───────────────────────────────────────────────────────────────────────────────────
A missing value is the ABSENCE OF DATA in a record where a value is expected.

Representations: NULL, NaN, N/A, NA, blank, empty, "-", "unknown"

Example: In our Titanic dataset:
┌────────────────┐
│ PassengerId    │ Age  │ Cabin │
├────────────────┤
│ 1              │ 22.0 │  -    │  ← Missing Cabin
│ 6              │ NaN  │  E46  │  ← Missing Age
│ 181            │ NaN  │  NaN  │  ← Missing both
└────────────────┘

TYPES OF MISSING DATA:
───────────────────────────────────────────────────────────────────────────────────

1. MCAR - MISSING COMPLETELY AT RANDOM
   ──────────────────────────────────────
   
   Definition: Missingness has NO relationship to any variable
   
   Characteristics:
   • Occurs randomly across all observations
   • No predictable pattern
   • Most benign type of missing data
   
   Real-world example:
   • Survey respondent accidentally skips a question
   • Database field corrupted by random server error
   • Handwritten form lost in filing accident
   
   Statistical test (Little's MCAR test):
   • If p-value > 0.05: Data is MCAR
   • If p-value < 0.05: Data is NOT MCAR (either MAR or MNAR)
   
   Treatment: Can use simple deletion or imputation
             Results will have minimal bias
   
   In Titanic: Embarked column is likely MCAR (just 2 random errors)


2. MAR - MISSING AT RANDOM
   ──────────────────────────
   
   Definition: Missingness depends on OBSERVED variables, not the missing variable
   
   Characteristics:
   • Missingness has a pattern explained by other data
   • Missing data is "random" CONDITIONAL on other variables
   • More common than MCAR in real-world data
   
   Real-world example:
   • Older passengers less likely to report income
     → Missing income depends on Age (observed variable)
     → Income itself not the reason for missingness
   
   • Certain schools don't report test scores
     → Missing scores depend on School Type (observed)
     → Score levels themselves not the reason
   
   Statistical requirement:
   • Must use methods that account for other variables
   • Simple deletion introduces bias (violates MAR assumption)
   
   Treatment: Multiple imputation (MI), model-based imputation,
             KNN imputation using other variables
   
   In Titanic: Age column is likely MAR
             • Missing slightly more in 3rd class
             • Missingness depends on observed Pclass
             • Use Pclass + Sex to impute Age


3. MNAR - MISSING NOT AT RANDOM
   ───────────────────────────────
   
   Definition: Missingness related to the missing value itself
   
   Characteristics:
   • The reason someone is missing = the value they would have
   • Most problematic type of missing data
   • Cannot be fixed with observed data alone
   
   Real-world example:
   • People with low income reluctant to report salary
     → Missing values tend to be for LOW earners
     → Missingness = information about the value
   
   • Unemployed people skip job title question
     → Missing job title = likely unemployed
     → Value itself drives missingness
   
   • Patients with severe symptoms avoid follow-up
     → Missing health scores = worse health
     → High values more likely to be missing
   
   Why it's problematic:
   • Imputation cannot fix this with available data
   • Need external information or domain expertise
   • Simple deletion heavily biases results
   
   Treatment: Sensitivity analysis, domain expert consultation,
             specialized MNAR models
   
   In Titanic: Cabin is partially MNAR
             • Missing cabin = poor record keeping
             • Pattern = lower class passengers
             • Missingness related to ship operations


COMPARISON TABLE:
───────────────────────────────────────────────────────────────────────────────────

Type  │ Definition            │ Example              │ Treatability │ Risk
──────┼───────────────────────┼──────────────────────┼──────────────┼────────
MCAR  │ Completely random     │ Form lost in mail    │ Easy ✓       │ Low ✓
MAR   │ Random given other    │ Missing by income    │ Medium       │ Medium

WHY MISSING VALUES MATTER:
───────────────────────────────────────────────────────────────────────────────────

1. ANALYTICAL BIAS
   • Removes systematic patterns from data
   • Results not representative of true population
   • Example: Removing poor people from income analysis

2. STATISTICAL POWER
   • Reduces sample size → wider confidence intervals
   • P-values less reliable → harder to detect real effects
   • Example: 80% data loss → need much larger true effect

3. MODEL PERFORMANCE
   • Many algorithms require complete data
   • Missing values degrade predictions
   • Can bias model coefficients and importance

4. VALIDITY
   • Conclusions based on incomplete data
   • May invalidate statistical test assumptions
   • Example: T-test assumes representative sample

5. REPRODUCIBILITY
   • Different deletion strategies → different results
   • Makes research difficult to reproduce
   • Prevents comparison across studies


SUMMARY:
───────────────────────────────────────────────────────────────────────────────────

Missing Value = Absence of data where value expected

Three Types:
  MCAR = Random, safe to delete (but imputation better)
  MAR = Pattern related to other variables, need group-based imputation
  MNAR = Value-related missingness, risky, needs careful analysis

In Titanic Dataset:
  Cabin = MNAR/Systematic (ship operations)
  Age = MAR (class-based pattern)
  Embarked = MCAR (random errors)

Key Point: DON'T just delete! Understand type first.

QUESTION 2: WHY CAN BLINDLY DELETING ROWS BE RISKY?
═════════════════════════════════════════════════════════════════════════════════════

DEFINITION:
───────────────────────────────────────────────────────────────────────────────────

"Blindly deleting rows" = removing ALL rows containing ANY missing value
(Also called "listwise deletion" or "complete-case analysis")

In Titanic:
  Original rows: 891
  Rows with ANY missing: 714 (80.25%)
  Rows remaining: 177
  Data surviving: Only 19.75%

What is Statistical Power?
  = Ability to detect real patterns/differences in data
  = Function of sample size (larger n = more power)
  = Needed for reliable statistical tests

Impact of 80% Data Loss:

Original sample:         n = 891

Reduction factor:        4.8x smaller

Standard errors:         ← Larger (less reliable)

Regression slopes:       ← Less stable

Example Calculation:

With n=891:   ±3.2% margin of error

For survival rate estimation:
With n=891:   Can detect differences as small as 6%
With n=177:   Can only detect differences of 13%

CONSEQUENCE: Cannot detect real differences in smaller subgroups


PROBLEM #4: STATISTICAL TEST VIOLATIONS
───────────────────────────────────────────────────────────────────────────────────

Most statistical tests assume:
  1. Data is representative of population
  2. Sample was drawn randomly
  3. No systematic selection bias

Blind deletion VIOLATES these assumptions!

Example: T-test for Age comparison

Assumption: Sample means are unbiased estimators of population means

Before deletion:
  • 1st class mean age: 37.3 years (mostly complete data)
  • 3rd class mean age: 25.1 years (lost 84% to deletion)
  • Result: Valid comparison

After blind deletion:
  • 1st class mean age: 37.3 years (unchanged)
  • 3rd class mean age: 28.4 years (BIASED UPWARD!)
  • Why? Deleted younger, poorer 3rd-class kids with missing data
  • Result: Age difference appears FALSELY LARGE

T-test conclusions now INVALID because:
  • 3rd class sample not representative of actual 3rd class
  • Age difference inflated by selection bias
  • P-value and conclusions unreliable

SMARTER ALTERNATIVES TO BLIND DELETION
═════════════════════════════════════════════════════════════════════════════════

✅ OPTION 1: TARGETED DELETION
───────────────────────────────────────────────────────────────────────────────────

Principle: Only delete rows where CRITICAL variables are missing

Code:
  # Only require Survived (target) and key features to be complete
  df_clean = df.dropna(subset=['Survived', 'Sex', 'Pclass', 'Age', 'Fare'])
  
  # Keep rows even if Cabin is missing (not critical)
  # Cabin is dropped separately due to sparsity

Result:
  • Preserves 80%+ of data
  • Only removes rows truly needed for analysis
  • Minimizes bias

When to use:
  • 1-5% missing in critical columns
  • Clear distinction between critical and optional features


✅ OPTION 2: MEAN/MEDIAN IMPUTATION
───────────────────────────────────────────────────────────────────────────────────

Principle: Fill missing values with mean or median of that column

Age Imputation:
  df['Age'].fillna(df['Age'].median(), inplace=True)

Pros:
  ✓ Simple
  ✓ No data loss
  ✓ Preserves sample size

Cons:
  ✗ Loses variance in Age
  ✗ Creates artificial ties at median
  ✗ Doesn't preserve group differences

Result:
  All Age values now between 0.42 and 80
  Missing values set to 28 (median)
  Distribution becomes bimodal (real + artificial peak at median)

When to use:
  • Quick exploratory analysis
  • No critical relationships between groups
  • NOT for publication-quality work


✅ OPTION 3: GROUP-BASED IMPUTATION (RECOMMENDED)
───────────────────────────────────────────────────────────────────────────────────

Principle: Impute using group medians (preserves patterns)

Code for Age:
  df['Age'] = df.groupby(['Pclass', 'Sex'])['Age'].transform(
      lambda x: x.fillna(x.median())
  )

Group medians:
  • 1st class, Female: 35 years
  • 1st class, Male: 41 years
  • 2nd class, Female: 26 years
  • 2nd class, Male: 30 years
  • 3rd class, Female: 22 years
  • 3rd class, Male: 24 years

Pros:
  ✓ No data loss
  ✓ Preserves group patterns
  ✓ More realistic than single mean
  ✓ Maintains variance within groups
  ✓ Respects demographic structure

Cons:
  • Slightly reduces variance
  • Creates artificial ties within groups
  • More complex than simple mean

Result:
  ✓ 0 missing Age values
  ✓ Group patterns preserved
  ✓ Realistic age distributions by class
  ✓ Full sample size retained

When to use:
  • 10-50% missing in non-critical columns
  • Clear grouping variables available
  • Want to preserve demographic patterns
  • BEST CHOICE for most real-world scenarios


✅ OPTION 4: K-NEAREST NEIGHBORS (KNN) IMPUTATION
───────────────────────────────────────────────────────────────────────────────────

Principle: Find k similar records, use their average for imputation

For Age:
  For each passenger with missing age:
    1. Find 5 most similar passengers (by Pclass, Sex, Fare, Parch, SibSp)
    2. Average their ages
    3. Use as imputation value

Example:
  Passenger 6: Missing Age
  Similar passengers found:
    • Passenger 23: Age 24, 3rd class, male, Parch=1
    • Passenger 45: Age 26, 3rd class, male, Parch=1
    • Passenger 67: Age 22, 3rd class, male, Parch=2
    • Passenger 89: Age 25, 3rd class, male, Parch=1
    • Passenger 101: Age 23, 3rd class, male, Parch=1
  Average: (24+26+22+25+23)/5 = 24
  Impute Age 6 = 24

Pros:
  ✓ Very sophisticated
  ✓ Uses information from multiple variables
  ✓ Preserves variance and patterns
  ✓ Most realistic imputation

Cons:
  ✗ Computationally intensive
  ✗ Assumes similarity measures are valid
  ✗ More complex to implement

Result:
  ✓ 0 missing values
  ✓ Highly realistic imputed values
  ✓ Preserves local patterns and correlations

When to use:
  • 10-40% missing data
  • Multiple variables available for similarity matching
  • Want highest-quality imputation
  • Publication-quality research


✅ OPTION 5: MULTIPLE IMPUTATION
───────────────────────────────────────────────────────────────────────────────────

Principle: Create multiple datasets with different imputations

Process:
  1. Create 5-10 imputed datasets (each with different Age values)
  2. Run analysis on each dataset separately
  3. Combine results using statistical formulas

Why this works:
  • Accounts for uncertainty in imputation
  • Better confidence intervals
  • Proper statistical inference

Pros:
  ✓ Accounts for imputation uncertainty
  ✓ Valid statistical inference
  ✓ Best for publication-quality work
  ✓ Standard in epidemiology/social science

Cons:
  ✗ Complex implementation
  ✗ Computationally expensive
  ✗ Results harder to interpret

When to use:
  • Publication-quality research
  • Need valid statistical inference
  • High-stakes decisions
  • >20% missing data
